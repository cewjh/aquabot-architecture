# ADR-006: Single-Brain Parallel ReAct Loop & Zero-Cost Streaming Synthesis

* **Status:** Accepted
* **Context:** The earlier 3-stage architecture used a primary model call for tool routing, a secondary hidden non-streamed `responseSchema` call to pick bundle SKUs from dumped catalog lists, and a third streamed synthesis pass. While safe against hallucinated SKUs, dumping large catalogs into a stateless secondary JSON selector added redundant latency/token burn, severed conversational vision reasoning from product selection, and relied on fragile keyword heuristics when intents varied. Meanwhile, static quick-reply chips drifted out of sync with the conversation language.
* **Decision:**
  1. **Single-Brain 5-Tool Static ACI & Schema Thought Slots:** Consolidate orchestration into one **Domain-Agnostic Bounded Native ReAct Loop** backed by a static 5-tool `read` / `write` Tool Registry: `calculate_aquarium_specs`, `search_catalog`, `create_cart_bundle` (initial setup/package creation), `modify_cart` (incremental cart operations: `add` / `remove` / `set_quantity` / `replace` / `clear`), and `handoff_to_whatsapp`. All declarations use standard JSON Schema (`parametersJsonSchema` with `additionalProperties: false`) and equip search with a leading `intent` field (**Schema-Level Thought Slot**) so assumptions stabilize prior to execution.
  2. **KV-Cache Prefix Stability (Static Prefix, Native `AUTO`) & Parallel Reads:** Keep the 5 tool declarations fixed across every step in native `AUTO` mode so prompt-prefix KV caching stays intact and the orchestrator remains completely provider- and domain-agnostic. Run independent read-only calls concurrently via `Promise.all`, execute write mutations sequentially, and interleave multi-search suggestions round-robin.
  3. **Fail-Loud Self-Correcting Boundaries:** Validate explicit `variant_id` and SKU bounds deterministically inside `create_cart_bundle` / `modify_cart`, rejecting invalid variants with `available_variants` (never silently downgrading) and executing atomic `replace` swaps so the ReAct loop self-corrects within the same turn.
  4. **Bounded Safety, Sliding-Tail `<quick_replies>` & Graceful Wrap-Up:** Guard execution with `maxSteps = 8`, per-turn spend ceiling, a `(toolName, normalizedArgs)` loop circuit breaker (`seenCount > 2`), a tool-free wrap-up synthesis fallback, and `$0` sliding-tail SSE `<quick_replies>` extraction.
* **Alternatives Considered:**
  1. *Keep Dual-LLM Non-Streamed JSON Selection:* Guarantees schema structure, but doubles LLM round-trips and duplicates prompt/catalog tokens.
  2. *Single Polymorphic Cart Mega-Tool + Forced Decoding Modes:* Overloads one write schema with both full-bundle metadata and 6 incremental mutation modes, magnifying branching complexity and delimiter-boundary errors under strict grammar lockups.
  3. *Mid-Loop Dynamic Tool Removal for a Small Toolset:* Filters schemas per step, but invalidates prompt-prefix KV caches and decouples conversational history from active tool schemas.
  4. *Unbounded Loop or Separate Quick-Reply Call:* Exposes Edge quotas/TTFB to looping and unnecessary inference hops.
* **Consequences & Trade-offs:**
  * **Pros:** Richer conversational continuity (vision + variant reasoning in one context), preserved KV-cache prefix across turns, shallow single-purpose write schemas with higher accuracy on compact models, fail-loud self-correction on invalid SKUs/variants, and multilingual dynamic follow-up chips at `$0` additional inference cost.
  * **Cons:** Requires strict backend SKU/stock/variant verification across both `create_cart_bundle` and `modify_cart`, variant-aware `retrieval_context` formatting, canonical `Read -> Write -> Synthesize` multi-turn history reconstruction, and intent-driven prompting so catalog product language does not override user reply language.
